# 2026-08-29

## botter-shop-mic 项目排障记录

- canal-service ↔ search-service 曾存在 Maven 循环依赖（IDE 报"模块循环不支持注解处理"），用户自行解决：MysqlListener 改为通过 MQ 发送 CanalMessage，不再直接引用 search 的 GoodsEsRepository。共享消息类（CanalMessage/OperationType/BeanUtils）已下沉到 common 模块。
- 排查 search-service 不消费 canal 消息问题：确认 RabbitMQ（localhost:5672, vhost /，管理口 15672，注意管理插件 stats 被禁用、/api/consumers 不可用，用 queue get API + requeue 模式查消息）。结论：canal.queue 和 queue 均为空，且日志出现 "Direct message:"（receiveMessage 的日志）而非 "send message:"（sendCanalMessage 的日志），判定运行中的 canal-service 是旧构建，消息发错了队列。方案：Rebuild + 重启 canal-service。
- 后续验证：用户重启后消息确实进入 canal.queue，但新错误——MqSender.sendCanalMessage 被误加了 @RabbitListener(queues=CANAL_QUEUE)，canal-service 自己消费 canal.queue 且参数类型 CanalMessage 与 String 消息不匹配，MessageConversionException 后消息被丢弃（无死信队列），search 仍收不到。已删除该注解（发送方法只做编程式调用）。排查此类问题的关键线索：报错栈里的 "Endpoint handler details" 会显示被注册成监听器的方法。
- ES 环境：本机 Docker ES 8.19.5，端口 9200，索引 goods_es_info，mapping 在 search-service/src/main/resources/mapping/goods_es_info.json（注意该 mapping 未覆盖 id/price/stock/specsMap 等字段，依赖动态映射）。
- GoodsService.ExportMysqlToEs 的 catch 块吞异常不打日志，只抛 GlobalException(ES_SERVICE_ERROR)，根因难定位；后续排查时建议先加 log.error。
- 架构：eureka 8761，search-service 18003，canal-service 18005，canal server 11111（destination: example，订阅 goods\..*），goods-service 通过 Feign（GoodsApi，返回 Result<GoodsDTO>）。
